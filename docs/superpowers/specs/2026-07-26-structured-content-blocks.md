# Structured Content Blocks for DB Chat

> **Date:** 2026-07-26
> **Status:** Draft
> **Ticket:** Implements Option B — replacing plain Markdown with typed content blocks for richer rendering of data-analysis results.

---

## 1. Problem

The assistant currently returns all content as a single Markdown string (`message.content`). This means:

- **Tables** are written as GFM Markdown tables — unstyled, non-interactive, no type-aware formatting (numbers not right-aligned, nulls not handled).
- **Charts** require a special ` ```chart ` code-block hack that the model must manually copy from the tool result.
- **Code** has no syntax highlighting.
- **Lists, headings, text** have no semantic structure — they are just HTML generated by `react-markdown`.

The model already returns structured data from every tool (`columns`, `rows`, `chart specs`, `reports`), but then has to flatten it into Markdown and the renderer has to re-parse it. This is wasteful, lossy, and produces poor UI.

## 2. Solution: Structured Content Blocks

The model emits a JSON array of typed content blocks delimited by ` ```blocks `. Each block has a `type` and type-specific fields. The renderer splits the message content at block boundaries, renders Markdown for text segments, and dispatches each block to a dedicated React component.

### 2.1 Model Output Format

The model writes Markdown as before, but can insert a ` ```blocks ` code block containing a JSON array of content blocks at any point. Content *before* and *after* the blocks is rendered as normal Markdown.

**Example output:**

```markdown
Here are the results:

```blocks
[
  {"type":"heading","level":3,"text":"Sales by Region"},
  {"type":"table","columns":["Region","Revenue","Growth"],"rows":[
    {"Region":"North","Revenue":125000,"Growth":"+12%"},
    {"Region":"South","Revenue":98000,"Growth":"+8%"},
    {"Region":"East","Revenue":142000,"Growth":"+15%"}
  ]},
  {"type":"chart","chartType":"bar","columns":["Region","Revenue"],"rows":[
    {"Region":"North","Revenue":125000},
    {"Region":"South","Revenue":98000},
    {"Region":"East","Revenue":142000}
  ],"title":"Revenue by Region"}
]
```

The North region leads with $125K, followed by East at $142K...
```

### 2.2 Block Types

#### `text`
Rich text rendered with a minimal Markdown processor (inline formatting only).

```typescript
interface TextBlock {
  type: 'text';
  content: string;        // Markdown — inline bold, italic, links, code
}
```

#### `heading`
```typescript
interface HeadingBlock {
  type: 'heading';
  level: 1 | 2 | 3 | 4;
  text: string;
}
```

#### `table`
The primary block type for query results. Renders as a rich data table matching the inspector's results tab.

```typescript
interface TableBlock {
  type: 'table';
  columns: string[];
  rows: Record<string, unknown>[];
  columnTypes?: Record<string, 'string' | 'number' | 'date' | 'boolean'>;  // for alignment
  caption?: string;
}
```

Rendering:
- Header row with `--color-control` background, bold 11px font
- Body cells with border separators, 12px font
- Numeric columns right-aligned (`font-variant-numeric: tabular-nums`)
- Null values shown as an em dash (`—`)
- Row hover highlight
- Scrollable on overflow

#### `chart`
```typescript
interface ChartBlock {
  type: 'chart';
  chartType: 'bar' | 'line' | 'area' | 'pie' | 'scatter' | 'radar' | 'radialBar' | 'composed' | 'funnel' | 'treemap' | 'sunburst';
  columns: string[];
  rows: Record<string, unknown>[];
  title?: string;
  nameKey?: string;
  valueKeys?: string[];
  options?: {
    stacked?: boolean;
    layout?: 'vertical' | 'horizontal';
    donut?: boolean;
  };
  series?: Array<{ key: string; type?: 'bar' | 'line' | 'area'; name?: string }>;
}
```

Same format as the current `visualize_data` tool output. The model can either:
- Call `visualize_data` and include the returned data in a blocks array (recommended)
- Construct the chart spec directly

#### `code`
```typescript
interface CodeBlock {
  type: 'code';
  language: string;
  content: string;
}
```

Rendered with a code header showing the language and a copy button. Syntax highlighting via a lightweight highlighter (Prism or `shiki`).

#### `list`
```typescript
interface ListBlock {
  type: 'list';
  ordered: boolean;
  items: string[];          // each item is inline Markdown
}
```

#### `divider`
```typescript
interface DividerBlock {
  type: 'divider';
}
```

### 2.3 Rendering Pipeline

```
message.content
    │
    ▼
[ContentSplitter]
    │  Splits on ```blocks ... ``` boundaries
    ▼
[Segments]
    ├── MarkdownSegment(text before blocks)  → ReactMarkdown (inline-only)
    ├── BlocksSegment(json array)            → BlockRenderer
    │                                           ├── TextBlock    → MinimalMarkdown
    │                                           ├── HeadingBlock → styled <hN>
    │                                           ├── TableBlock   → RichTable (SortableTable)
    │                                           ├── ChartBlock   → ChartBlock (existing)
    │                                           ├── CodeBlock    → CodeBlock (syntax highlight)
    │                                           ├── ListBlock    → styled <ul>/<ol>
    │                                           └── DividerBlock → <hr>
    └── MarkdownSegment(text after blocks)  → ReactMarkdown (inline-only)
```

### 2.4 BlockRenderer Component

Located at `src/renderer/components/BlockRenderer.tsx` (new file, new directory).

```tsx
interface BlockRendererProps {
  blocks: ContentBlock[];
}

function BlockRenderer({ blocks }: BlockRendererProps) {
  return (
    <div className="content-blocks">
      {blocks.map((block, i) => {
        switch (block.type) {
          case 'text':    return <TextBlockView key={i} block={block} />;
          case 'heading': return <HeadingView key={i} block={block} />;
          case 'table':   return <RichTableView key={i} block={block} />;
          case 'chart':   return <ChartBlock key={i} spec={JSON.stringify(block)} />;
          case 'code':    return <CodeBlockView key={i} block={block} />;
          case 'list':    return <ListView key={i} block={block} />;
          case 'divider': return <hr key={i} className="content-divider" />;
          default:        return null;
        }
      })}
    </div>
  );
}
```

### 2.5 RichTableView Component

Uses the same styling as `src/renderer/styles.css` `.result-table` block:

- `<table>` with sticky header
- `<th>` sorted by column type
- Numeric columns: `className="numeric"`, `text-align: right`, `font-variant-numeric: tabular-nums`
- Null values: em dash, `className="null"`, tertiary color
- Row hover: `background: var(--color-control-hover)`
- First column: left padding for visual hierarchy
- Scroll container: `overflow: auto`

### 2.6 CodeBlockView Component

```tsx
function CodeBlockView({ block }: { block: CodeBlock }) {
  const [copied, setCopied] = useState(false);
  return (
    <div className="code-block-wrap">
      <div className="code-block-header">
        <span>{block.language}</span>
        <button onClick={() => { navigator.clipboard.writeText(block.content); setCopied(true); }}>
          {copied ? <Check size={14} /> : <Copy size={14} />}
        </button>
      </div>
      <pre className="code-block-body">
        <code>{block.content}</code>
      </pre>
    </div>
  );
}
```

Adds CSS classes:
- `.code-block-wrap`: border radius, overflow hidden
- `.code-block-header`: flex row, background `--color-control`, border-bottom, small padding
- `.code-block-body`: same as existing `.transcript-content pre`

Syntax highlighting can be added later by replacing `<code>{content}</code>` with a lightweight highlighter.

### 2.8 System Prompt Changes

Add to the agent system prompt:

```
## Content Format

You can present structured data (tables, charts, code) using content blocks.
To use blocks, wrap a JSON array of block objects in a fenced code block with
the language "blocks":

```blocks
[
  {"type":"table","columns":["Name","Value"],"rows":[{"Name":"A","Value":10}]}
]
```

Block types:
- `table`: columns + rows of data. Include columnTypes for numeric alignment.
- `chart`: chart specification. Use visualize_data tool and include its output here.
- `code`: code snippet with language annotation.
- `heading`: section heading with level (1-4).
- `list`: ordered or unordered list of items.
- `text`: rich text paragraph (inline Markdown).
- `divider`: horizontal separator.

Use blocks for any structured data. Regular prose should remain as plain Markdown
outside blocks.
```

## 3. Migration Path

**Backward compatibility:** The ` ```blocks ` fence is new. Old messages without blocks continue to render as regular Markdown. The `message.content` field is unchanged. No storage migration needed.

**Phase 1 (this PR):**
1. Create `ContentSplitter` utility
2. Create `BlockRenderer` + all block view components (`RichTableView`, `CodeBlockView`, `ListView`, `HeadingView`, `TextBlockView`)
3. Reuse existing `ChartBlock` for chart type
4. Wire into `ReactMarkdown` via a custom `code` component override (checking for `language-blocks`)
5. Add CSS for all new block components
6. Update system prompt with block format instructions
7. Remove the old ` ```chart `-specific code in favor of the generalized blocks parser
8. Keep backward compatibility: ` ```chart ` blocks still work (parsed as chart blocks)

**Phase 2 (future):**
- Syntax highlighting for code blocks
- Copy button for code blocks
- Sortable table columns
- Inline table editing

## 5. Open Questions

1. **Should blocks replace Markdown entirely?** — No. Prose paragraphs are still better as Markdown. Blocks are for structured data (tables, charts, code). The model chooses what to put in blocks vs plain text.
2. **How does the model learn the format?** — System prompt examples + tool descriptions that reference blocks.
3. **What about streaming?** — Blocks are parsed after the full message is received. Streaming continues to work as before (text-delta events).
4. **Should tables support sorting?** — Phase 2. Phase 1 renders static tables that match the inspector's look.

## 6. Success Criteria

- A model-generated table via ` ```blocks ` renders with proper borders, padding, numeric alignment, and hover states — visually matching the inspector results table
- Chart blocks work exactly as before (model calls `visualize_data`, includes output in blocks array)
- Code blocks render with a language header and copy button
- Messages without blocks render identically to before (backward compatible)
- All existing tests pass
